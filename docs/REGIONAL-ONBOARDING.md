# Regional onboarding workflow

1. Send the public creator questionnaire to the regional lead.
2. The lead submits identity, visual direction, homepage priorities, modules, contributors, and mobile needs.
3. The coordinator opens the protected submissions inbox and forwards the generated website and logo prompts to the developer.
4. The developer implements the prompt as a new regional config/presentation/assets set inside this repository.
5. The developer creates a new deployment target with isolated data, credentials, domain, and editor access.
6. The regional lead reviews desktop/mobile pages and provides the final portraits, account credentials, and content approvals.
7. The blockchain/security team separately approves staking before writes are enabled.

Kudi Hub and Shanghai Crypto are examples of regional outcomes; neither is the universal visual template. The universal template is the shared behavior and configuration contract in this repository.
